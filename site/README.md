# The site

<https://shergin.github.io/baton/>: the documentation site, generated by
this crate and deployed from `master` by `.github/workflows/pages.yml`.

The repository's rule holds here: no generated code, operation text,
diagnostic or store on the site is typed by hand. Every figure is a
directory under [`figures/`](figures/), a `baton.json` and the host files
beside it, Swift and Kotlin, that `batonc` compiles when a page asks for it;
the page shows the host as its author wrote it, the code the compiler
generated, an operation's text as `print` prints it, a lens's accessors from
the report, or a diagnostic pointing into the host. Every store is a dump
the runtime wrote under the fixtures of [`spec/`](../spec/), and every
script plate is a script of the specification, step by step. The
repository's own docs (`docs/`, the READMEs, the changelog, the contract)
are the text of most pages; the site adds plates under their headings and
rewrites their links. The site-authored chapters live in
[`content/`](content/).

```sh
scripts/build-compiler.sh                      # the compiler the figures are compiled with
cargo run --manifest-path site/Cargo.toml      # writes site/dist
./site/build.sh                                # the same, plus the compiler's wasm build for the playground
python3 -m http.server 4173 --directory site/dist
```

The generator finds `batonc` in `BATON_COMPILER`, else at
`compiler/target/release/batonc`, else at `compiler/target/debug/batonc`.

A `{{directive}}` on a line of its own in any page becomes a plate:

| directive | shows |
|---|---|
| `{{host <figure> [file]}}` | the host files, SwiftUI beside Compose |
| `{{generated <figure> [file] [shared]}}` | what the compiler generated |
| `{{operation <figure> <Name>}}` | an operation's text, variables and id |
| `{{lens <figure> <Name>}}` | a fragment's or an operation's lens, from the report |
| `{{diagnostics <figure>}}` | the diagnostics of a figure with an error in it |
| `{{source <path> [lines=a-b]}}` | a repository file as code |
| `{{json <path>}}` | a JSON file, pretty printed |
| `{{records <dump> [only=k,k] [notified=k.f,k.f] [roots]}}` | a dump from `spec/` as records |
| `{{normalize <spec/case>}}` | a response beside the records it became, linked |
| `{{case <name>}}` | a manifest case's reads |
| `{{script <name> [steps=1,2]}}` | a script from `spec/scripts/`, step by step |
| `{{stage <figure> <Operation> <dump> [rows=n]}}` | a screen over real records; click a field |
| `{{releases}}` | the releases, from the changelog |
| `{{playground}}` | the playground, driven by the wasm build |

A caption follows a `|`. Consecutive fences tagged `tab`, a Swift one and a
Kotlin one, become one block of tabs, and a reader's choice of platform
holds across the page and across visits. `SITE_CONTACT_SHEET=1 cargo run
--manifest-path site/Cargo.toml` also writes `dist/contact/`, every figure
with its diagnostics on one page, for proofing.

The playground runs the compiler itself: `batonc` built for
`wasm32-wasip1`, unchanged, under a WASI shim with an in-memory file
system ([`static/wasi/`](static/wasi/), vendored from
`@bjorn3/browser_wasi_shim`), driven by
[`static/playground.js`](static/playground.js). What the reader types is
written to that file system as a `.graphql` host beside a `baton.json`, the
same `generate` and `print` commands run, and the outputs are read back.
